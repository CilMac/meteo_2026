## Commandes
- `python3 -m http.server 8765` : serveur local (puis http://localhost:8765/). Si git ou python3 rouvrent en boucle la fenêtre « outils de ligne de commande » : Xcode.app est trop ancien pour macOS 26, `sudo xcode-select -s /Library/Developer/CommandLineTools` règle le problème (fait le 15/11/2026).
- `npm test` : tests unitaires (Node, sans dépendance, données synthétiques).
- `npm run live` : contrôle de cohérence sur de vraies données pour les 8 favoris.
- `npm run check-deploy -- https://cilmac.github.io/meteo_2026/` : compare le site publié aux fichiers locaux.
- `npm run verif-rando` (ou `node scripts/verif-rando.mjs [--dir …] [--detail] [--offline]`) : fiabilité de la vue 🥾. Lit tous les exports du dossier `Exports_Fiabilite/` (relevés réunis sans doublon) et les compare aux stations horaires de Météo-France (data.gouv.fr, « Données climatologiques de base - horaires », fichiers `H_<dépt>_latest-…csv.gz`, publiés vers 7 h jusqu'à 4-5 h UTC du jour : vérifiable le lendemain). Heures MF en UTC (vérifié contre le METAR de Saint-Dizier), RR1/FXI = heure qui se termine à HH, T/FF = à HH. Station la plus proche par grandeur (pluie ≤ 15 km, autres ≤ 30 km), départements choisis grâce à la liste des communes de geo.api.gouv.fr (aucune position envoyée), cache dans le dossier temporaire (`meteo-verif-cache`). Calculs dans `scripts/verif-rando-lib.mjs` (testés). France seulement ; METAR (IEM, `asos.py`) possible pour l'étranger : température au degré entier, cumul `p01m` inutilisable en France (toujours 0), seul le code « RA » dit qu'il pleut. `Exports_Fiabilite/` contient des positions : ne jamais le publier. **Quand l'utilisateur dit « vérifie »** (choix du 21/11/2026, plutôt qu'une commande à lancer lui-même ou un rapport HTML, envisagé plus tard) : Claude lance `npm run verif-rando` et présente un bilan commenté (tendances, biais, limites, nombre d'heures), **toujours accompagné de graphiques** (demandé le 22/11/2026, widget en ligne dans la conversation) : chiffres clés (écart moyen ou biais de température, vent, rafales, pluie), courbes de température prévu/mesuré (mesuré en trait plein, chaque relevé en pointillés distincts), vent et rafales prévu/mesuré ; barres de pluie prévue/mesurée dès qu'il a plu ; avec plusieurs lieux ou nuits, un graphique par relevé ou un bilan par échéance plutôt qu'un fouillis de courbes. Données heure par heure : `node scripts/verif-rando.mjs --detail --offline`.
- `node scripts/backtest-j7.mjs [--cities agay,paris] [--from 2024-03-01]` : mesure l'erreur réelle des prévisions à 1, 3, 5 et 7 jours (API Previous Runs d'Open-Meteo contre réanalyse ERA5, avec la climatologie comme référence). ## Règles à ne pas casser (cahier des charges v1.1)
- Aucune donnée inventée ; absente = « — », jamais 0 (un vrai 0 mm reste « 0 mm »).
- Chaque valeur est étiquetée avec son modèle ; Météo-France n'est jamais présenté comme source d'une valeur venant d'un autre modèle.
- Vent : maxima (« vent max », « rafales max »), jamais « moyenne ». Probabilité et quantité de pluie ne se mélangent pas.
- Vigilance officielle : « non confirmée » + lien si elle n'est pas vérifiable ; jamais « verte » par déduction. Seul le Canada (ECCC) est lu ; alertes reproduites sans modification, avec l'attribution de la licence.
- Lien « Weather data by Open-Meteo.com » toujours visible (même repliée, la carte Sources laisse l'attribution affichée).
- Aucun pourcentage de fiabilité inventé.

## Fiabilité mesurée (ne pas la redécouvrir)
Mesures sur 2024-03 → 2026-10, prévisions « émises N jours avant » (API Previous Runs d'Open-Meteo : ECMWF IFS, GFS, GEM ; Météo-France non archivé au-delà de J+3).
- Température max à 7 jours : erreur moyenne 2,3 °C (ECMWF), 2,0 °C (moyenne des 3), contre 3,3 °C pour la climatologie (vérité ERA5, 8 villes). Mieux que « la température habituelle », mais gain de la combinaison faible (~0,3 °C).
- **Quantité de pluie à 7 jours : non fiable** (vérité = pluviomètres Météo-France, 5 villes françaises, 4 715 jours) : classe sec/faible/modéré/fort juste 49-52 % contre 60 % en annonçant toujours « sec » ; erreur moyenne 2,3-2,6 mm/jour contre 2,15 mm pour « toujours 0 mm » ; quantité juste à ×2 près sur 32-36 % des jours pluvieux. À 5 jours : à peine mieux que rien. À 3 jours : correct (classe juste 68 %). « Pluie oui/non » à 7 jours : 72 % contre 71 % pour « toujours sec ». Même verdict avec ERA5 comme vérité.
- Le cumul d'une semaine garde un peu d'information (total juste à ×2 près dans 63 % des cas), mais les modèles sous-estiment (rapport médian 0,7-0,9).
- Non testé : la médiane de scénarios de l'application (ensembles non archivés).
- Outils : `scripts/backtest-j7.mjs` (température, vent, pluie contre ERA5 ; `--offline` pour ne lire que le cache, `--rain` pour le détail) et `scripts/backtest-pluie-mf.mjs --data <dossier>` (pluie contre les pluviomètres : « Données climatologiques de base - quotidiennes » sur data.gouv.fr, un dossier par département ; cumul Météo-France = 06 h UTC J → 06 h UTC J+1). L'API gratuite d'Open-Meteo a une limite horaire : ne pas relancer ces mesures en boucle.
